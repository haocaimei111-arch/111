# 社区新增-视频｜原型评审与查漏补缺

> 本文基于《社区新增-视频 (1).md》及所附原型图整理，为原 PRD 的补充评审稿，不替代原文档。原型中的文字批注仅作为界面参考，不视为新增需求。

# 一. 评估结论

现有文稿已覆盖首页混流、视频播放、发布、转码、审核、个人主页、后台和基础指标，可以进入交互评审，但尚不建议直接进入完整开发。开发前必须补齐播放队列、作品状态机、浏览人数口径、上传恢复、审核版本、下载鉴权及完整埋点，否则客户端、服务端和数据团队会产生不同实现。

本次交互原型已覆盖：首页三种信息架构、视频详情、播放/暂停、上下滑动切换、详情评论抽屉、分享与下载、发布设置、上传/转码/审核进度、审核驳回、个人主页及作品管理。

## 1.1 本期范围

- 支持单条视频作品，视频可携带标题、创作描述、标签、关联角色、创作声明、AI 生成声明、可见范围及下载权限。
- 支持首页视频/图文混流、视频详情播放、互动、分享、举报、下载和个人主页展示。
- 支持 MP4、MOV；单文件不超过 300 MB；时长大于 0 秒且不超过 180 秒；最短边不低于 480 px。
- 支持 480P、720P、1080P 多清晰度；最高档不得超过源视频分辨率。
- 上传、转码、审核均成功后方可公开发布。

## 1.2 非本期范围

- 视频与图片混发、多视频发布、直播、合拍、站内拍摄和站内剪辑。
- 弹幕、倍速播放、横屏播放、画中画、离线缓存和视频合集。
- 创作者收益、付费视频、商业推广及版权音乐库。

# 二. 必须修正的矛盾与缺口

| 编号 | 原文问题 | 风险 | 建议结论 |
|---|---|---|---|
| 1 | “浏览人数”与“同一用户重复进入计入浏览次数”口径冲突 | 前端展示与数据指标无法对齐 | 个人主页展示去重浏览人数 UV；重复进入只增加浏览次数 PV，不增加 UV。作者本人访问增加 PV，默认不增加 UV。 |
| 2 | 视频播放完全部队列后“循环至最初视频” | 容易造成重复消费和播放次数虚增 | 优先请求下一页；确实无更多内容时停止并提示“暂时没有更多内容”。若保留循环，循环播放必须沿用原播放会话并单独标记 `is_replay=true`。 |
| 3 | 登录用户与游客均只使用本地播放记忆 | 换设备后进度不一致，清缓存即丢失 | 登录用户进度服务端保存，本地作缓存；游客仅本地保存。每 5 秒或离开页面时更新，最长保留 7 天。 |
| 4 | 更换视频要求退出发布页重新选择 | 用户已填写内容可能丢失 | 发布页内提供“更换视频”；更换前二次确认，更换后保留文字和发布设置，清除旧文件上传进度、封面和时长信息。 |
| 5 | 封面固定取第一帧 | 第一帧可能黑屏、模糊或违规 | 默认使用服务端推荐帧；允许用户在视频帧中重新选择。封面需独立审核，失败时允许更换封面，不必重新上传视频。 |
| 6 | “转码成功+审核成功后发布”未说明执行顺序 | 任务耗时和失败恢复策略不一致 | 上传完成后转码与内容审核并行；两个任务均成功后进入发布写入。审核可使用源文件，外部播放只能使用转码文件。 |
| 7 | 仅描述审核失败提示“同图文” | 视频可能只有局部风险片段 | 驳回原因需区分视频、封面、标题、描述；视频驳回应返回风险时间点和可操作建议。 |
| 8 | 下载成功提示出现“本地相册相册” | 提示文案错误 | 统一为“已保存至本地相册”。 |
| 9 | 竖屏强制适配规则不足 | 横屏视频、超长视频可能拉伸或裁切 | 视频不得拉伸。竖视频等比居中；横视频按宽度等比缩放并上下留黑；方形视频居中展示。首期不旋转至横屏。 |
| 10 | 进度条拖动与上下滑动切换没有手势优先级 | 容易误切视频 | 进度条区域横向拖动只控制进度；视频区域纵向位移超过 60 px 才切换作品；评论抽屉展开时禁用切换手势。 |

# 三. 状态机补充

## 3.1 作品状态

| 状态 | 含义 | 用户侧展示 | 可执行操作 |
|---|---|---|---|
| `draft` | 本地或云端草稿，尚未提交 | 草稿箱展示 | 编辑、删除、继续上传 |
| `uploading` | 文件正在上传 | “上传中 xx%” | 后台继续、取消上传 |
| `processing` | 上传完成，正在转码 | “视频处理中” | 后台继续、查看状态 |
| `reviewing` | 正在进行内容审核 | “审核中” | 查看状态、删除 |
| `published` | 转码、审核和作品写入均成功 | 正常展示 | 查看、编辑文字、置顶、修改权限、删除 |
| `rejected` | 内容审核未通过 | 展示具体驳回原因 | 修改文字/封面或重新上传 |
| `failed` | 上传、转码或系统写入失败 | 展示失败阶段和重试入口 | 重试、重新上传、删除 |
| `offline` | 发布后被作者设为私密或被平台下架 | 作者可见状态标识 | 申诉、修改、删除 |
| `deleted` | 作品已删除 | 前台不可见 | 按数据策略保留审计记录 |

## 3.2 发布成功条件

发布成功必须同时满足：源文件上传完成、至少一个 H.264 兼容档位转码成功且最低达到 480P、内容与封面审核通过、作品关系写入成功、播放地址生成成功。任何条件未满足时不得进入公开信息流。

## 3.3 幂等与恢复

- 每次发布生成唯一 `publish_request_id`；重复点击发布不得生成多个作品。
- 分片上传支持断点续传；网络恢复后从已成功分片继续。
- 转码自动重试 1 次，使用同一 `job_id` 关联链路；人工重新转码需生成新的任务版本。
- 多端编辑草稿需校验版本号；冲突时提示“草稿已在其他设备更新，请刷新后重试”，不得静默覆盖。

# 四. 页面与交互补充

## 4.1 首页

- 首期建议采用原型方案 A：延续现有双列瀑布流，仅增加视频标识和时长，对图文结构改动最小。
- 视频卡片列表页不自动播放；进入详情并出现首帧后才计播放成功。
- 同一 `work_id` 在同一列表请求中去重；刷新后重新请求，返回列表时保持原浏览位置。
- 关注流无内容时提示“暂时没有关注内容，去发现更多创作者吧”。
- 封面加载失败时展示默认视频封面，保留标题和作者；点击仍可进入详情重试。

## 4.2 视频详情页

- 打开页面后立即申请播放地址并起播；首帧成功前显示加载状态。
- 轻击视频在播放与暂停间切换；播放按钮仅在暂停或加载失败时常显。
- 离开页面、进入后台、来电、其他音频抢占焦点时自动暂停；恢复前台后不自动播放，由用户主动继续。
- 上下滑动切换视频。切换后上一条立即暂停并记录进度，下一条仅在进入主视区后起播。
- 播放记忆：上次进度大于 5 秒且距结尾不少于 10 秒时续播；其余情况从头播放。
- 详情抽屉展开时视频移动至抽屉上方，保持当前播放/暂停状态；下拉抽屉或点击关闭回到播放页。
- 评论发送失败时保留输入内容并提示“发送失败，请重试”；重复点击发送只能生成一条评论。
- 播放过程中作品被下架时立即停止播放，提示“该内容暂不可查看”，并允许切换下一条。

## 4.3 分享与下载

- 分享复用图文渠道，增加下载入口；渠道至少包括微信好友、复制链接、生成分享图和举报。
- 下载按钮状态以服务端返回的 `can_download` 为准，客户端不得只读取本地缓存。
- 下载文件为审核通过的最高可用清晰度版本，不得返回源文件地址。
- 下载开始前检查相册权限和可用存储空间；任务进行中禁止重复创建。
- 下载过程中作者关闭权限，已获授权任务允许完成；新任务按最新权限拦截。
- 下载失败保留重试入口；网络恢复后不自动重新下载。

## 4.4 发布页

- 标题最多 20 个字符，创作描述最多 1000 个字符；服务端必须再次校验。
- 选择视频后立即执行格式、大小、时长、分辨率、文件可读性和剩余存储校验。
- 上传中退出页面时提供“后台继续”“保存草稿并暂停”“放弃发布”三种处理。
- 文件上传完成前草稿需保留本地文件引用；原文件被系统删除时保留文字设置并提示重新选择视频。
- 作品包含 AI 生成技术时必须开启声明；关闭时需二次确认并提示违规后果。
- 发布按钮点击后展示上传、处理、审核三个阶段；任务进入后台后在消息中心通知最终结果。

## 4.5 个人主页

- 视频卡片展示播放标识；置顶标识位于右上角，播放标识居中，两者不得重叠。
- 仅作者本人在“已发布”页查看浏览人数；他人主页不展示该指标。
- 长按或更多菜单支持置顶、编辑文字、修改可见范围、修改下载权限和删除。
- 编辑标题、描述、标签、关联角色、封面后生成新审核版本；审核通过前继续展示旧版本。
- 删除操作需二次确认；接口幂等，删除失败时保留卡片并允许重试。

# 五. 核心指标口径补充

| 指标 | 建议口径 |
|---|---|
| 视频发布渗透率 | 当日成功发布至少 1 条视频的去重用户数 / 当日活跃用户数。草稿、上传失败和审核拒绝不计入。 |
| 视频消费渗透率 | 当日至少产生 1 次首帧成功事件的去重用户数 / 当日活跃用户数。仅进入详情但未出现首帧不计入。 |
| 人均视频播放时长 | 当日所有有效播放会话的实际观看时长总和 / 当日至少观看 1 条视频的去重用户数。后台播放、卡顿和暂停时间不计入。 |
| 视频完播率 | 自然播放至 100% 的播放会话数 / 首帧成功的播放会话数。拖动直接跨至结尾、失败会话和自动循环回放单独标记。 |
| 视频互动率 | 视频产生的点赞、评论、收藏和分享次数 / 视频有效曝光次数。取消点赞等反向行为不计入正向互动。 |
| 浏览人数 UV | 详情首屏成功展示后的去重访问人数。登录用户按账号去重，游客按匿名设备标识去重；爬虫和异常流量不计入。 |
| 播放次数 | 每个 `play_session_id` 首帧成功后计 1 次；同一会话暂停、继续或拖动不重复计数。 |
| 首帧成功率 | 首帧成功的播放会话数 / 发起播放请求的会话数。 |
| 卡顿率 | 播放中发生至少一次卡顿的播放会话数 / 首帧成功的播放会话数。首帧加载不计为播放中卡顿。 |

# 六. 埋点补充

通用曝光、点击、点赞、评论、收藏、关注、分享和举报复用图文事件名，并增加 `media_type=video`。必须新增以下视频专属事件：

| 页面 | 事件名 | 核心参数 | 说明 |
|---|---|---|---|
| 视频详情 | `video_play_start` | `play_session_id、work_id、autoplay、network_type` | 发起一次播放请求。 |
| 视频详情 | `video_first_frame` | `play_session_id、startup_duration_ms、resolution、codec` | 首帧成功，用于播放次数和起播成功率。 |
| 视频详情 | `video_play_progress` | `progress_percent、watch_duration_ms、play_position_ms` | 25%、50%、75%、100%各上报一次。 |
| 视频详情 | `video_play_end` | `watch_duration_ms、completion_rate、end_reason` | 页面离开、切换作品、播放失败或自然结束。 |
| 视频详情 | `video_buffer_start/end` | `buffer_duration_ms、resolution、network_type` | 记录卡顿次数与时长。 |
| 视频详情 | `video_play_fail` | `play_stage、error_code、cdn_node` | 区分起播失败、播放中断和切档失败。 |
| 视频详情 | `video_quality_change` | `from_resolution、to_resolution、change_type` | 区分自动和手动切换。 |
| 发布页 | `video_select_result` | `file_size、video_duration_ms、format、error_code` | 本地素材校验结果。 |
| 发布页 | `video_upload_start/result` | `upload_id、elapsed_ms、retry_count、error_code` | 上传任务链路。 |
| 发布页 | `video_publish_result` | `publish_request_id、failed_stage、error_code` | 最终发布结果。 |
| 服务端 | `video_transcode_result` | `job_id、template_version、output_resolutions、error_code` | 转码任务结果。 |
| 服务端 | `video_audit_result` | `audit_version、audit_type、risk_type、risk_timestamp` | 机器及人工审核结果。 |

# 八. 开发前待确认事项

1. 视频详情是否保留“播放完全部队列后循环至第一条”；建议取消整队列循环。
2. 登录用户播放进度是否需要跨端同步；建议首期服务端保存。
3. 作者本人是否计入浏览人数 UV；建议不计入，但计入浏览次数 PV。
4. 是否允许用户自选封面；建议首期支持从视频帧截取。
5. 审核驳回是否提供风险时间点；若内容安全服务不支持，需要明确降级文案。
6. 视频编辑是否允许更换封面；建议允许，且新版本审核期间展示旧版本。
7. 下载清晰度是否固定最高档，还是允许用户选择；首期建议固定最高可用档。
8. 删除作品后的源文件、转码文件、审核记录及统计数据分别保留多久。

# 九. 验收重点

- 首页图文与视频混排不重复、不跳位，返回列表保持浏览位置。
- 首帧、暂停、恢复、拖动、上下切换和播放记忆符合统一播放会话口径。
- 弱网、断网、CDN 异常、无 H.265 能力设备均可恢复或回退 H.264。
- 上传、转码、审核、发布各阶段状态可查询，重复提交不会产生重复作品。
- 下载权限变化、相册权限关闭、存储不足和重复下载均有明确处理。
- 个人主页播放标识、置顶标识、浏览人数及作品状态不重叠、不泄露作者侧数据。
- 埋点可以还原单次播放会话，并与服务端转码、审核和发布链路通过 `trace_id` 关联。
